HOW TO REASSEMBLE THIS PROJECT
------------------------------
The brief asks for three separate source archives. Extract all three into the
SAME parent folder - each zip creates one top-level folder - to get the layout
the build and test scripts expect:

    <anywhere>\PROG2002-A3\
        ng-client\        <- from 24833044A3-clientside.zip
        ng-admin\         <- from 24833044A3-adminside.zip
        prog2002-a3\      <- from 24833044A3-api.zip (this archive)

    i.e. extract, then rename the three outer folders to ng-client,
    ng-admin and prog2002-a3 if your unzip tool appended anything.

QUICKEST WAY TO SEE IT RUNNING
------------------------------
1. Create the database (MySQL 8):

       mysql -u root -p < prog2002-a3\api\sql\charityevents_db.sql

   (or import that file through phpMyAdmin / MySQL Workbench)

2. Start the API:

       cd prog2002-a3\api
       npm install
       rem check the DB_CONFIG password in config/env.js (there is NO .env file)
       npm start                   -> http://localhost:3000/api/health

3. Start the client website:

       cd ..\..\ng-client
       npm install
       npx ng serve --port 4200    -> http://localhost:4200

4. Start the admin website:

       cd ..\ng-admin
       npm install
       npx ng serve --port 4300    -> http://localhost:4300

Angular v22 requires Node 22.22.3+ or 24.15+ (node -v to check).

SIMPLER: ONE SERVER FOR EVERYTHING
----------------------------------
Both websites are already built into api\public, so a single command serves the
API and both websites from one origin (this is also how cPanel is set up):

       cd prog2002-a3\api
       npm install
       npm start            ->  client: http://localhost:3000/
                                admin:  http://localhost:3000/admin/

CONFIGURATION
-------------
There is no .env file and no dotenv package. The database connection is written
as plain JavaScript in prog2002-a3\api\config\env.js (DB_CONFIG block) and
mirrored in prog2002-a3\api\event_db.js, following the Assessment 2 approach.
Edit that one block, not environment variables.

NO MYSQL AVAILABLE?
-------------------
USE_DEMO_FALLBACK is true in config\env.js. The API then serves a bundled sample
dataset in read-only mode so both websites still work, and prints a clear warning
explaining that writes are disabled.
